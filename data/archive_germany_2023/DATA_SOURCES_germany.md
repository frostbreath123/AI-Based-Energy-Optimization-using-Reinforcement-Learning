# Data sources and provenance

Generated by `python -m energyrl.data.manifest`. Real data are all for **Germany, calendar year 2023** (PV for Berlin). Measured/processed public data, derived data and synthetic data are labelled separately.

## PVGIS hourly PV output (SARAH3), 1 kWp reference system
- **Class:** processed public data
- **Publisher:** European Commission, Joint Research Centre (PVGIS v5.3)
- **URL:** https://re.jrc.ec.europa.eu/api/v5_3/seriescalc
- **Retrieved:** 2026-10-27
- **Units:** W per kWp (converted to kW per kWp); also T2m in deg C
- **Resolution:** hourly (UTC, minute 11)
- **Geography:** Berlin, Germany (lat 52.52, lon 13.405)
- **License:** PVGIS data free to use with attribution (c) European Union, JRC; verify terms at https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis_en
- **Preprocessing / notes:** UTC stamps floored to the hour, W->kW, clipped to [0,1] kW/kWp, converted to Europe/Berlin local time.
- **Role in simulation:** Actual on-site PV generation profile = capacity factor x installed kWp x scenario scale.
- **Local files (data/raw):** pv_pvgis_berlin_2023.csv

## Day-ahead spot price, bidding zone DE-LU
- **Class:** processed public data
- **Publisher:** Fraunhofer ISE Energy-Charts API; data from Bundesnetzagentur | SMARD.de
- **URL:** https://api.energy-charts.info/price?bzn=DE-LU
- **Retrieved:** 2026-10-27
- **Units:** EUR/MWh (converted to EUR/kWh)
- **Resolution:** hourly
- **Geography:** Germany-Luxembourg bidding zone
- **License:** CC BY 4.0 (stated in the API response: 'CC BY 4.0 from Bundesnetzagentur | SMARD.de')
- **Preprocessing / notes:** Resampled to hourly mean, /1000, local time. Negative prices kept in the spot series; the customer tariff is floored at 0.
- **Role in simulation:** Wholesale component of the electricity tariff (the tariff = spot x scale + network adder + levies).
- **Local files (data/raw):** prices_de_lu_2023.json

## Public net electricity generation by source, Germany
- **Class:** derived from public data + literature factors
- **Publisher:** Fraunhofer ISE Energy-Charts API (Bundesnetzagentur / ENTSO-E based)
- **URL:** https://api.energy-charts.info/public_power?country=de
- **Retrieved:** 2026-10-27
- **Units:** MW per source type
- **Resolution:** 15 min, resampled to hourly mean
- **Geography:** Germany
- **License:** Energy-Charts states CC BY 4.0 for its data (the API response itself carries no licence field; verify at https://www.energy-charts.info).
- **Preprocessing / notes:** Per-source MW averaged hourly; null/negative -> 0; carbon intensity = sum(generation x emission factor) / sum(generation). Imports/exports and pumped-storage charging excluded (production-based intensity).
- **Role in simulation:** Time-varying grid carbon intensity (gCO2e/kWh).
- **Local files (data/raw):** public_power_de_2023_01.json, public_power_de_2023_02.json, public_power_de_2023_03.json ...

## Emission factors per generation technology
- **Class:** literature constants
- **Publisher:** IPCC AR5 WGIII (2014) Annex III, Table A.III.2 (median lifecycle): coal 820, gas CCGT 490, biomass 230, geothermal 38, hydro 24, nuclear 12, solar PV utility 48, onshore wind 11, offshore wind 12 gCO2e/kWh
- **URL:** https://www.ipcc.ch/report/ar5/wg3/
- **Retrieved:** n/a
- **Units:** gCO2e/kWh
- **Resolution:** constant
- **Geography:** global medians
- **License:** IPCC reports: free for non-commercial use with citation
- **Preprocessing / notes:** Lignite (1000), oil (650), coal-derived gas (600), waste (400), others (500) are ANALYST ASSUMPTIONS (not IPCC values) - see config/default.yaml.
- **Role in simulation:** Convert the generation mix into carbon intensity.

## Time-of-use network charge + levies
- **Class:** SYNTHETIC (generated)
- **Publisher:** this project
- **URL:** -
- **Retrieved:** n/a
- **Units:** EUR/kWh
- **Resolution:** hourly
- **Geography:** stylised German industrial customer
- **License:** project code (MIT-style, educational)
- **Preprocessing / notes:** Schedules A (training) and B (OOD) defined in config/default.yaml; they mimic peak/shoulder/off-peak structures but are not a real utility tariff.
- **Role in simulation:** Peak / intermediate / off-peak structure added to the real spot price.

## Industrial base load, production jobs, deadlines, forecast errors, PV drops
- **Class:** SYNTHETIC (generated)
- **Publisher:** this project
- **URL:** -
- **Retrieved:** n/a
- **Units:** kW, hours
- **Resolution:** hourly
- **Geography:** stylised manufacturing site
- **License:** project code
- **Preprocessing / notes:** Generated by energyrl/scenarios.py from seeded random draws; no real plant data was used (none freely available at suitable resolution).
- **Role in simulation:** Flexible/inflexible loads, job power, durations, release times, deadlines.

## Coherence and limitations of combining sources

- PV is for Berlin; price and carbon are national (DE-LU / Germany). Both lie in the same weather-driven German system and the same calendar year, so correlations (sunny hour -> cheaper power) are preserved, but Berlin irradiance is only a proxy for the national solar fleet.
- Timestamps from all sources are UTC and aligned before conversion to Europe/Berlin local time. The two DST-transition days (and one day with a data gap) are dropped (362 of 365 days kept).
- Gaps up to 3 h are linearly interpolated; no values were imputed beyond that.
- The industrial plant, job schedules and network tariff are synthetic. Conclusions about absolute savings apply to this stylised site, not to a specific real factory.
